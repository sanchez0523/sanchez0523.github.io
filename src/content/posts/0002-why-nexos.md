나는 Grafana의 열렬한 사용자였다. 지금도 그렇다.

그런데 ESP32로 온습도 센서를 띄워놓고 "지금 값이 어떻게 되지?"를 보려고 할 때마다,
결국 Grafana 대시보드를 **처음부터 만들어야** 하는 게 짜증스러웠다.
InfluxDB 소스 연결, 쿼리 작성, 패널 배치, 시간 범위 설정, 색 조정...

**작은 장난감 프로젝트에 쓰려고 만들어진 도구가 아니다.**

## 이미 있는 도구들

| 도구 | 문제 |
|------|------|
| Grafana | 엔터프라이즈 중심. 설정 지옥 |
| Home Assistant | IoT 전반. 개발자용이 아님 |
| ThingsBoard | 기능 과잉. Docker 10개 |
| Node-RED | 플로우 기반. 학습곡선 |
| EMQX Dashboard | 브로커 관점. 메시지 뷰어 |

**"ESP32 꽂으면 카드가 자동으로 뜨는 것"** 이건 비어 있다.

## Nexos의 가치 제안

한 문장: *설정 없이 MQTT 토픽을 대시보드 카드로 자동 변환.*

구체적으로:

1. `docker compose up` 한 줄로 시작
2. 디바이스에서 `devices/esp32-01/temperature` 토픽 발행
3. 대시보드 카드가 **자동으로** 생성됨
4. 임계값 넘으면 웹훅으로 알림

Auto-Discovery가 핵심. 사용자가 설정할 게 없다.

## 왜 "자체 호스팅"만 지원하나

클라우드 SaaS로 만들면 돈이 되긴 하겠지만,
IoT 개발자들은 **자기 데이터를 자기가 쥐는 걸** 좋아한다.
나도 그렇다. 그래서 그렇게 만든다.

## 왜 공개로 만드나

혼자 만들면 외로워서 포기한다. 공개로 만들면 피드백이 동력이 된다.
스타 하나 받을 때마다 조금씩 더 쓸 수 있다.

## 언제 나오나

v0.1 MVP는 2026 Q2 목표. MQTT → TimescaleDB → SvelteKit 대시보드 파이프라인이 끝나면 첫 릴리스.

그 전까지는 여기에 매주 기록을 남긴다.
